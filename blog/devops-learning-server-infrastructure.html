DevOps Learning Server Infrastructure

20 November 2026 • Project 15 / 15

Pendahuluan

Project ini berbeda dari project Proxmox saya yang lama pada bulan September. Waktu itu fokusnya masih pada instalasi Proxmox, virtualisasi dasar, dan menjalankan satu VM Debian. Kali ini, di bulan November, lingkungan yang saya bangun berkembang menjadi infrastruktur pembelajaran DevOps yang lebih luas: beberapa VM dengan peran berbeda, jaringan virtual yang menghubungkan semuanya, dan akses jarak jauh supaya lab bisa saya pakai dari luar jaringan lokal.

Alasan pengembangannya cukup praktis. Tools seperti Ansible, Docker, dan Kubernetes lebih masuk akal dipelajari ketika ada beberapa mesin dengan peran yang berbeda dan saling terhubung, bukan hanya satu VM serba guna. Saya juga ingin melatih sisi operasionalnya: bagaimana mesin-mesin itu diberi alamat, bagaimana trafik antar mesin diatur, dan bagaimana akses dari luar dikendalikan. Jadi project ini bukan hanya soal memasang layanan, tetapi soal merancang lingkungan tempat layanan-layanan itu belajar hidup bersama.

Pembelajaran sebelumnya banyak membantu di sini. Pengalaman server hardware dan Proxmox menjadi fondasi platformnya, lab jaringan memberi bekal routing antar VM, dan pembelajaran WireGuard serta Tailscale sebelumnya menjadi dasar akses jarak jauhnya. Semua itu bertemu dalam satu lingkungan yang saya sebut sebagai learning environment dan eksperimen teknis yang sengaja dibatasi untuk belajar.

Tujuan

  • Membangun lingkungan pembelajaran DevOps multi-VM di atas Proxmox VE dengan peran yang saling melengkapi.
  • Mempraktikkan routing antar VM menggunakan MikroTik CHR sebagai router virtual.
  • Menggunakan Ansible untuk otomatisasi konfigurasi antar VM.
  • Menyediakan tempat belajar Docker/Kubernetes serta storage dan Git pada VM yang terpisah.
  • Mengaktifkan remote access dengan SSH dan Tailscale, serta mempelajari firewall sebagai kontrol akses.

Tools / Perangkat

  • Server fisik dan Proxmox VE sebagai hypervisor.
  • MikroTik CHR sebagai router jaringan virtual.
  • VM Ubuntu Server untuk Ansible.
  • VM Ubuntu Server untuk Docker dan Kubernetes.
  • VM Debian untuk storage, Git, dan project.
  • SSH dan Tailscale untuk akses dan remote access.
  • Firewall untuk pembelajaran kontrol akses dan trafik jaringan.

Proses yang Dilakukan

  1. Melakukan troubleshooting hardware server terlebih dahulu agar platform berjalan stabil.
  2. Menyiapkan Proxmox VE sebagai tempat seluruh VM berjalan.
  3. Menjalankan MikroTik CHR untuk routing jaringan virtual antar VM.
  4. Membuat VM Ubuntu untuk Ansible sebagai titik otomatisasi konfigurasi.
  5. Membuat VM Ubuntu lain untuk eksperimen Docker dan Kubernetes.
  6. Membuat VM Debian untuk storage, Git, dan project.
  7. Menghubungkan semuanya melalui routing antar VM, menyiapkan SSH, memasang Tailscale untuk remote access, dan menerapkan aturan firewall.

Pembagian VM saya rancang berdasarkan peran, bukan sekadar jumlah. Ubuntu untuk Ansible menjadi tempat saya belajar mengotomatiskan konfigurasi mesin lain; Ubuntu untuk Docker/Kubernetes menjadi wadah eksperimen container dan orchestration dalam skala lab; Debian menjadi tempat storage, Git, dan project disimpan, sehingga data pembelajaran punya rumah yang jelas. MikroTik CHR menghubungkan semuanya, dan di sinilah pengetahuan networking saya terpakai lagi: VM dengan peran berbeda perlu rute yang benar untuk saling berkomunikasi, dan trafik antar peran itu bisa saya amati serta kendalikan.

Tailscale saya gunakan untuk membantu remote access dari luar jaringan lokal, melanjutkan apa yang sudah saya pelajari pada lab VPN sebelumnya. Dengan begitu lab bisa saya akses seperti gaya kerja remote atau WFH, tanpa harus membuka seluruh layanan ke jaringan luar. Firewall menjadi bagian dari pembelajaran kontrol akses dan trafik: aturan dibuat untuk mengizinkan jalur yang memang dibutuhkan, seperti SSH dan koneksi Tailscale, sambil membatasi sisanya. Bagi saya, memasang firewall di sini bukan sekadar menyalakan fitur keamanan, tetapi berlatih memutuskan siapa boleh mengakses apa.

Kendala / Hal yang Diperhatikan

Bagian awal project ini diisi troubleshooting hardware server. Sebelum VM bisa berjalan stabil, kondisi perangkat perlu diperiksa dan dibereskan terlebih dahulu; pengalaman ini mengingatkan saya bahwa lapisan fisik tetap menjadi fondasi yang tidak bisa dilewati, betapapun menariknya lapisan virtual di atasnya. Setelah platform stabil, tantangan berpindah ke sisi jaringan dan akses.

Routing antar VM adalah hal yang perlu diperhatikan dengan teliti. Ketika satu VM tidak dapat menjangkau VM lain, penyebabnya sering kali bukan layanan yang berjalan di dalamnya, melainkan rute atau aturan firewall di antaranya. Karena itu saya memeriksa konektivitas antar peran secara bertahap, memastikan setiap VM dapat mencapai yang lain sesuai kebutuhan, sebelum menganggap layanan di dalamnya bermasalah. Untuk remote access, aturan firewall juga harus seimbang: cukup terbuka untuk SSH dan Tailscale yang saya butuhkan, tetapi tidak membuka akses yang tidak diperlukan. Kesalahan kecil pada aturan dapat mengunci akses saya sendiri ke lab, sehingga perubahan aturan perlu diuji satu per satu.

Hasil dan Pemahaman

Hasil akhirnya adalah lingkungan belajar dengan beberapa VM yang saling terhubung sesuai perannya. Ansible dapat menjangkau VM target untuk latihan otomatisasi, eksperimen Docker dan Kubernetes berjalan pada VM Ubuntu yang terpisah, dan Debian menjadi tempat storage serta Git untuk project. Routing melalui MikroTik CHR membuat komunikasi antar VM berjalan, dan pengujian konektivitas antar peran menunjukkan lingkungan ini dapat dipakai untuk belajar, bukan hanya berdiri sebagai kumpulan VM.

Remote access melalui kombinasi SSH dan Tailscale memungkinkan lab diakses dari luar jaringan lokal, sesuai tujuan awal saya. Firewall yang menyertainya membuat akses tersebut tetap terkendali, dan proses menyusun aturannya sendiri menjadi bahan belajar tentang kontrol akses dan trafik jaringan.

Dari project ini saya memahami bahwa infrastruktur pembelajaran perlu dirancang berdasarkan peran dan konektivitas, bukan ditumpuk tanpa arah. Setiap VM punya alasan untuk ada, dan jaringan di antaranya adalah bagian dari desain, bukan kebetulan. Saya menyebut seluruh lingkungan ini sebagai learning environment dan eksperimen teknis: cukup nyata untuk melatih keterampilan DevOps, tetapi tidak saya klaim sebagai sistem yang siap dipakai untuk kebutuhan operasional skala besar.

Environment ini membantu saya melihat server, jaringan, remote access, dan automation sebagai satu sistem yang saling terhubung.

Hal yang Dipelajari

  • Lingkungan DevOps lebih mudah dipelajari ketika VM dibagi berdasarkan peran yang jelas.
  • Routing antar VM dan firewall adalah bagian dari desain lingkungan, bukan pelengkap.
  • Ansible, Docker/Kubernetes, dan storage/Git dapat ditempatkan pada VM terpisah agar eksperimen tidak saling mengganggu.
  • Tailscale dan SSH memungkinkan remote access yang tetap terkendali oleh firewall.
  • Troubleshooting hardware di awal mengingatkan bahwa lapisan fisik adalah fondasi lingkungan virtual.
  • Infrastruktur pembelajaran perlu disebut sesuai skalanya: lab dan eksperimen, bukan sistem operasional.

Kesimpulan

Dari sekadar menginstal Proxmox dan satu VM Debian di bulan September, kini saya memiliki lingkungan dengan beberapa peran yang saling terhubung dan bisa diakses dari luar jaringan lokal. Perkembangan itu bukan hanya soal jumlah VM, tetapi soal cara saya merancang infrastruktur: mulai dari peran, konektivitas, dan kontrol akses, bukan dari layanan yang ingin dipasang.

Project ini juga menjadi tempat bertemunya tiga jalur pembelajaran saya selama ini: jaringan, server, dan keamanan akses. Semuanya terpakai dalam satu lingkungan yang masih akan terus berkembang, dan bagi saya itulah bentuk belajar yang paling menyenangkan: membangun sesuatu yang nyata, lalu memahami mengapa ia bekerja seperti itu.
